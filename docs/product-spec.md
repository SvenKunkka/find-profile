# Find Profile · 产品规格说明书 (Product Spec)

## 1. 项目身份

| 项 | 值 |
| --- | --- |
| 项目名称 | Find Profile |
| App 名称 | Find Profile |
| 平台 | macOS（macOS 优先，其他平台暂不考虑） |
| 技术栈 | Tauri + Rust + React + TypeScript + SQLite FTS5 |
| 文档版本 | v0.1（MVP 立项） |

## 2. 产品定位

Find Profile 是一款 **macOS 文件快速检索工具**，对标 Windows 平台的 **Everything**。

它解决的核心问题：
- macOS 自带的 Spotlight 在搜索 NAS 上的文件时表现不佳（不索引非启动卷、断开后丢失结果、查询慢）。
- 一般文件搜索工具是"查的时候才扫盘"，在 NAS 上卡顿明显。
- 用户希望像 Everything 一样：**输入即出**、**纯本地索引查询**、**即使 NAS 断开也能看到上次索引到的文件名/路径**。

Find Profile 的差异化：**第一类公民支持 `/Volumes` 下挂载的 NAS 卷**，并把"本地目录"和"NAS 目录"作为两种不同语义的索引根来管理。

## 3. 目标用户

- 在 macOS 上使用 NAS（SMB/AFP/NFS 挂载到 `/Volumes`）存档大量素材、项目文件、归档资料的个人或小团队。
- 摄影师、剪辑师、设计师、研究人员、开发者——文件多、目录深、命名讲究，需要按文件名快速定位。
- 受不了 Spotlight 在 NAS 场景下表现的用户。

## 4. 核心使用场景

1. 用户挂载若干 NAS 卷到 `/Volumes`，把它们作为索引根加入 Find Profile，触发首次全量扫描。
2. 用户随时呼出 Find Profile，在搜索框输入关键词（部分文件名或路径片段），毫秒级看到结果列表。
3. 用户对结果"打开文件"或"在 Finder 中显示"。
4. NAS 暂时断开时，搜索仍然能命中上次索引的旧记录（标注为不可用），点开时给出友好错误提示。
5. NAS 重连后，用户手动触发"重新扫描"，索引被刷新。

## 5. 产品目标 (Goals)

- **快**：搜索查询命中本地 SQLite 索引，毫秒级返回。
- **稳**：宁可少功能，不要白屏、不要丢索引数据。
- **简**：UI 密集、纯工具感，无任何花哨元素。
- **支持 NAS**：把 `/Volumes` 下挂载点作为一等公民。
- **可重复**：扫描可重复运行而不损坏索引。

## 6. 核心产品原则

1. 搜索必须查询本地 SQLite 索引，不允许在请求时实时扫盘。
2. MVP 只索引文件元数据，不索引文件内容。
3. NAS 根**绝不能**因为 NAS 暂时断开就丢掉旧索引数据。
4. 本地根可以用文件系统监听（FS watch）。
5. NAS 根使用手动扫描 + 定时扫描，不依赖 watch。
6. 可靠性优先于高级特性。
7. UI 必须密集、简单、快速、工具感。

## 7. 功能列表 (MVP)

MVP 必须交付以下能力：

1. **添加本地目录** 作为索引根（`local`）。
2. **添加 `/Volumes` 下的 NAS 目录** 作为索引根（`nas`）。
3. **递归扫描目录**，遍历选中根下的所有子目录。
4. **索引文件元数据**：路径、文件名、扩展名、大小、修改时间。
5. **SQLite + FTS5 搜索**：能按文件名和路径片段进行全文搜索。
6. **结果列表展示**：文件名、所在目录、大小、修改时间、所属根。
7. **打开文件**：调用系统默认应用。
8. **在 Finder 中显示文件**：选中并定位。
9. **手动重新扫描**：对单个根触发 rescan。
10. **NAS 断开时保留旧索引**：根标记 `disconnected`，记录保留可查询。
11. **（后续）本地目录文件变化监听**：MVP 末期或 V2 引入 watch。
12. **（后续）NAS 目录定时扫描**：MVP 末期或 V2 引入 scheduler。

> 第 11、12 项在文档中列入路线图，但允许在 MVP 后期或 V2 才真正落地。

## 8. 不做事项 (Non-Goals)

明确**不做**的事，避免范围蔓延：

1. 不索引文件内容（不读 PDF/Word/代码正文）。
2. 不做 OCR（图片/扫描件不做文字识别）。
3. 不自己实现 SMB/NFS 协议——只读取 macOS 已经挂载好的 `/Volumes` 路径。
4. 不做云同步（索引数据不上传，不跨设备同步）。
5. 不做 AI 语义搜索（不做 embedding、不做问答、不做"找像 X 那样的图"）。

## 9. 关键非功能性要求

- **启动速度**：冷启动 < 2 秒进入可交互。
- **搜索延迟**：在百万级文件索引下，按文件名前缀搜索 < 100ms。
- **索引落盘**：所有索引必须落到本地 SQLite 文件，关闭应用后不丢失。
- **崩溃面**：单个 Tauri command 失败不能导致前端白屏；初次渲染必须独立于后端可用性。
- **平台**：macOS 优先（暂不投入 Windows / Linux）。

## 10. 成功判据

MVP 验收标准：

- 能添加 1 个本地目录 + 1 个 NAS 目录作为根。
- 能完成首次扫描并写入 SQLite + FTS5。
- 能在搜索框输入关键词，列表里命中预期文件。
- 能"打开文件"和"在 Finder 中显示"。
- NAS 拔掉后，搜索仍能返回旧记录；命中条目点开能给出"NAS 不可用"的友好提示。
- 重新挂载 NAS 后手动 rescan，旧记录刷新成最新状态，且未丢失任何用户数据。
