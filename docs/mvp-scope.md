# Find Profile · MVP 范围 (MVP Scope)

本文档明确 **MVP 必须做的事** 和 **MVP 明确不做的事**，是范围控制（scope control）的唯一权威来源。任何超出本文档列出的功能，都视为"未来版本"，不进入 MVP。

## 1. MVP 一句话定义

> **macOS 上一个能搜本地目录、也能搜挂载在 `/Volumes` 下 NAS 卷的快速文件名搜索工具；查询走本地 SQLite + FTS5 索引；NAS 断了也不丢已有索引。**

## 2. MVP In-Scope（必做）

下列 12 项构成 MVP 的全部功能集。第 1–10 项是 MVP 验收的硬要求；第 11、12 项允许放在 MVP 末期或紧随其后的 V2，但需要在架构上预留位置。

### 2.1 必须在 MVP 内完成（硬性）

1. **添加本地目录** 作为索引根
   - 通过真实的 Tauri 目录选择对话框（`@tauri-apps/plugin-dialog`）选择路径。
   - 路径写入 `roots` 表，`kind=local`，`status=available`。

2. **添加 `/Volumes` 下的 NAS 目录** 作为索引根
   - 同样的对话框入口。
   - 路径以 `/Volumes/` 开头时自动识别 `kind=nas`。
   - 用户在 UI 上可以显式覆盖 kind（例如把外接 SSD 当 local 处理）。

3. **递归扫描目录**
   - 后端命令 `start_scan(rootId)` / `rescan_root(rootId)` 触发。
   - 使用 `walkdir` / `jwalk` 等递归遍历整个根。
   - 失败、权限拒绝、符号链接循环等情况要被吞掉并记录，不能让整个扫描崩。

4. **索引文件元数据**
   - 字段：路径、文件名、扩展名、大小、修改时间、是否目录。
   - 写入 `files` 表（`(root_id, path)` 唯一），同步进 `files_fts`。
   - 不索引文件内容。

5. **SQLite + FTS5 搜索文件名和路径**
   - 命令 `search_files(query, limit, offset)`。
   - 在 `files_fts` 上对 `name` 和 `path` 做匹配。
   - 返回结构化结果（含所属 root 信息和当前 root status）。
   - 在百万级索引下首屏返回 < 100ms 是目标，不达标在 MVP 内允许，但需要记录。

6. **列表展示搜索结果**
   - 至少展示：文件名、所在目录、大小、修改时间、所属根的标识（`local` / `nas` 标签 + 状态徽标）。
   - 默认排序：相关性优先；可按文件名、修改时间二级排序。
   - 不可用根（`disconnected` / `error`）的结果可见但视觉上弱化，行内标"不可用"。

7. **打开文件**
   - 命令 `open_file(fileId)`，使用 `tauri-plugin-opener` 调用 macOS 默认应用。
   - 文件不存在或所属根不可用时返回结构化错误。

8. **在 Finder 中显示文件**
   - 命令 `reveal_in_finder(fileId)`，调用 `open -R <path>` 或等价 API。
   - 不可用时同样给友好错误。

9. **手动重新扫描**
   - 每个根都有"Rescan"按钮，触发 `rescan_root(rootId)`。
   - UI 显示扫描进度（已扫描文件数），通过 Tauri Event 推送。
   - 扫描完成后**仅在成功时**清理"本次没看到"的旧记录。

10. **NAS 断开时保留旧索引**
    - 扫描启动前检测根目录可访问性；不可访问 → 标记 `disconnected`，**绝不**删除 `files` 中的现有记录。
    - 搜索仍命中这些旧记录。
    - 重连后用户手动 rescan，根回到 `available`，记录被增量更新。

### 2.2 允许进入 MVP 末期或 V2（软性，可推迟）

11. **本地目录文件变化监听**
    - 使用 `notify` crate 对 `kind=local` 的根做增量监听。
    - 不开启对 `nas` 根的 watch（FSEvents/SMB 不可靠）。
    - 如果 MVP 时间紧，可全部走"手动 rescan"，把 watch 推到 V2。

12. **NAS 目录定时扫描**
    - 在 `settings` 中存默认间隔（如 6 小时）。
    - 调度器只对 `kind=nas` 且 `status=available` 的根生效。
    - 如果 MVP 时间紧，同样可推到 V2。

## 3. Out-of-Scope（明确不做）

以下事项 **MVP 不做**，且在路线图上没有明确承诺。任何带这类味道的需求，都先转化为 issue/讨论，不在 MVP 内实现。

1. **不索引文件内容**
   - 不读 PDF、Word、Markdown、源代码等正文。
   - 搜索只能匹配文件名 / 路径片段。

2. **不做 OCR**
   - 图片、扫描件、影像里的文字不识别。

3. **不自己实现 SMB / NFS / AFP 协议**
   - 完全依赖 macOS 已经把 NAS 挂载在 `/Volumes/<volume>`。
   - 不内置网络协议栈、不做账号管理、不做凭证存储。

4. **不做云同步**
   - 索引数据库纯本地，不上云、不跨设备同步、不导出导入分享。

5. **不做 AI / 语义搜索**
   - 不做 embedding、不做向量检索、不做 RAG、不做"找像 X 那样的图"。
   - 不接入任何 LLM。

## 4. MVP 验收清单 (Definition of Done)

MVP 视为完成，需要同时满足：

- [ ] 能添加 ≥1 个本地目录根（自动识别为 `local`）。
- [ ] 能添加 ≥1 个 `/Volumes/...` NAS 根（自动识别为 `nas`）。
- [ ] 用户能显式把某个根的 kind 从自动判断改成另一种。
- [ ] 启动首次全量扫描，元数据进入 `files` + `files_fts`。
- [ ] 在搜索框输入关键词，能实时看到匹配结果列表。
- [ ] 列表项可双击打开（默认应用）。
- [ ] 列表项可"在 Finder 中显示"。
- [ ] 任何根可一键 Rescan；扫描中状态清晰可见。
- [ ] 拔掉 NAS 后，搜索结果仍包含旧 NAS 记录，且行内标"不可用"。
- [ ] 重连 NAS 并 rescan 后，根状态回到 `available`，记录被刷新且未丢失任何用户的其他根数据。
- [ ] 后端任意命令失败时，前端不白屏；错误进入状态栏 / toast。
- [ ] 应用关闭后再次打开，所有索引数据仍在。
- [ ] `cargo test` 通过；`npm run build` 通过。

## 5. 范围控制原则

1. **要做的事**只能从第 2 节里挑，不允许临时加新条目。
2. **不做的事**列表是只增不减；新出现的"想做"功能默认进入"不做"队列，需要显式审批才升级为路线图。
3. 任何"顺手做一下"的重构、抽象、UI 美化都需要重新评估范围；MVP 阶段不做超出本文档的工作。
4. 当某项需求模糊时，**默认按更小的范围实现**——先解决核心，再说扩展。
